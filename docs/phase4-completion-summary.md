#### 1.1 代码索引系统
- ✅ 本地仓库文件加载（支持 Java/TS/JS/Python/Markdown）

### 4. 技术决策记录

#### 核心决策（详见 ADR-001）

| 问题 | 决策 | 理由 |
|------|------|------|
| Q1: 代码源范围 | 本地仓库优先 | 降低复杂度，MVP 聚焦核心能力 |
| Q2: ChromaDB 部署 | 嵌入式 + 文件持久化 | 无需额外容器，调试方便 |
| Q3: Embedding 模型 | text-embedding-3-small | 性价比最高，API 稳定 |
| Q4: 索引语言范围 | Java/TS/Python + 文本兜底 | 覆盖当前项目，后续扩展 |
| Q5: 任务模型 | 同步索引 | 实现简单，小规模足够 |

#### 关键设计亮点

1. **状态推断逻辑**：内存 + Chroma 双层存储，服务重启自动恢复
2. **依赖注入**：单例模式 + lru_cache，便于测试
3. **错误码体系**：分类清晰（2000-索引/2100-向量库/2200-LLM）
4. **兼容接口**：支持旧版 `/api/v1/chat`，平滑迁移
5. **进度日志**：每 10% 输出一次，便于调试

## 🔧 技术债务与后续优化

### 已知限制（MVP 范围内可接受）

1. **行号精度**：近似算法（±5行误差）
   - 影响：中等（足以定位代码块）
   - 优化：Phase 5 引入 tree-sitter

2. **状态持久化**：内存存储
   - 影响：低（单 worker 无影响）
   - 优化：Phase 5 迁移到 Redis

3. **索引效率**：全量重建
   - 影响：中等（大仓库索引慢）
   - 优化：Phase 5+ 增量更新

4. **异步任务**：同步索引
   - 影响：低（小仓库可接受）
   - 优化：Phase 5+ Celery 异步

### 优化路线图

#### Phase 5（计划）
- [ ] 精确行号（tree-sitter 解析 AST）
